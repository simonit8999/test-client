# Безопасность: как уходят данные заявки

## Что происходит с данными

1. Клиент заполняет форму — данные лежат **только в памяти браузера** (`useState`), ничего не отправляется на сервер.
2. По кнопке «Отправить заявку в Telegram» формируется текст и открывается
   `https://t.me/<telegram_username>?text=<encodeURIComponent(текст)>`.
3. Дальше данные живут в чате Telegram. **Сайт статический: нет бэкенда, нет БД, нет логов заявок.**

Код: `src/screens/Screen5Confirm.tsx` (`handleSend`), валидация ника — `src/hooks/useConfig.ts`.

## Реальные риски (по убыванию значимости)

| Риск | Что именно | Насколько критично |
|---|---|---|
| **URL остаётся в истории** | имя, телефон, авто, комментарий попадают в query-строку `t.me` → остаются в истории браузера устройства и в логах Telegram | Средне. На личном телефоне — норма, на общем/витринном — номер увидит следующий |
| **Подмена telegram_username** | если у кого-то есть доступ к репозиторию, он может поменять ник и заявки уйдут другому | Высоко по последствиям, но защищается доступом: 2FA на GitHub, приватность репозитория, защита ветки `main` |
| **Попап заблокирован** | в WebView Instagram/VK/Telegram `window.open` может не открыться — заявка «потеряется» | Средне для конверсии; в шаблоне есть fallback «Скопировать текст» |
| **Referer-утечка** | при переходах URL с данными мог бы уехать на сторонний сайт | Низко: `meta referrer = strict-origin-when-cross-origin` + `noopener,noreferrer` |

## Чего бояться не нужно

- **Перехват в кафе/Wi-Fi.** `t.me` — HTTPS, GitHub Pages — HTTPS, HSTS у Telegram. Номер по сети в открытом виде не идёт.
- **«Номер сохранится на вашем сервере».** Сервера нет: только статические файлы на GitHub Pages, никакой аналитики и трекеров (кроме шрифтов Google).
- **XSS через поля формы.** React экранирует значения, а текст заявки уходит через `encodeURIComponent`.

## Что уже сделано правильно

- `window.open(url, '_blank')` с последующим `win.opener = null` — новая вкладка не получает доступ к родительскому окну (аналог `noopener`), но в отличие от `features='noopener'` мы можем отличить успешное открытие от заблокированного попапа.
- `<meta name="referrer" content="strict-origin-when-cross-origin">` в `index.html` — на сторонние сайты уходит только origin, без пути и query.
- Валидация `telegram_username` регуляркой `^[a-zA-Z0-9_]{5,32}$`; невалидный ник → кнопка Telegram скрывается, остаётся копирование.
- Никаких сетевых запросов с PII: `fetch` используется только для загрузки конфига клиента.
- Текст для пользователя «Нажимая кнопку, вы перейдёте в Telegram» — информирование о переходе.

## Рекомендации

**Оставить как есть (обязательный минимум)** — этого достаточно для демо и тарифа «Старт»: риск не в перехвате, а в том, что номер лежит в URL/истории и в чате Telegram.

**Дёшево улучшить:**
1. Fallback при заблокированном попапе: если `window.open` вернул `null` — скопировать текст в буфер и показать «Текст скопирован» (реализовано).
2. Очищать форму после успешной отправки (снижает риск на общем устройстве).
3. Не добавлять в текст заявки лишнее: комментарий и номер авто можно оставить, но если клиент параноит — оставлять только имя + телефон + слот, остальное дописывать в чате.

**Если клиент требует «по-взрослому» (тариф 24 900 ₽):**

| Вариант | Плюсы | Минусы |
|---|---|---|
| Telegram Bot API через Cloudflare Worker (20–30 строк) | PII не в URL, заявка приходит в чат с кнопками «Подтвердить/Отклонить», можно считать статистику | Появляется мини-бэкенд + токен бота в секретах |
| Formspree / Getform (готовый приём форм) | 5 минут внедрения | Зависимость от сервиса, бесплатный лимит, PII у третьей стороны |
| WhatsApp deep-link | привычно клиенту | те же свойства, что у Telegram-ссылки |

Для «Бизнеса» я бы продавал именно **бота**: это и приватнее, и выглядит дороже («заявка с кнопкой подтверждения прямо в Telegram»), а стоимость — бесплатный tier Cloudflare Workers.

## Итог

Архитектура «данные только в браузере + переход в Telegram» **безопасна с точки зрения перехвата** (TLS), но **не приватна**: номер остаётся в URL и истории. Для демо-продаж и «Старта» — приемлемо и объяснимо; для «Бизнеса» предлагайте бота. Обязательный минимум по доступам: 2FA на GitHub и защита ветки `main`, чтобы ник `telegram_username` нельзя было подменить незаметно.
